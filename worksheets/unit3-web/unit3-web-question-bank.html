السؤال الرابع: الأسئلة المقالية

  1. عرّف تطبيق الويب، واذكر ثلاثة أمثلة عليه.

  2. اذكر طبقات تطبيق الويب الثلاث، ودور كل منها ومكان عملها.
    الواجهة الأمامية: تعرض المحتوى وتستقبل ما يكتبه المستخدم (على المتصفح). الواجهة الخلفية: تعالج الطلبات وتطبّق قواعد التطبيق (على الخادم). قاعدة البيانات: تحفظ البيانات وتوفرها عند الحاجة وتنظمها (مكان التخزين).
  3. رتّب خطوات تعاون الطبقات الثلاث عند البحث عن منتج في متجر إلكتروني.
    1) الأمامية تستقبل كلمات البحث. 2) الأمامية ترسلها إلى الخلفية. 3) الخلفية تطلب من قاعدة البيانات المنتجات المطابقة. 4) قاعدة البيانات تعيد النتائج إلى الخلفية. 5) الخلفية تجهّز النتائج لإرسالها. 6) الأمامية تعرض النتائج على الشاشة.
  4. اشرح تشبيه المطعم لطبقات تطبيق الويب.
    الصالة والنادل = الواجهة الأمامية (تعرض قائمة الطعام وتستلم الطلب). المطبخ والطباخ = الواجهة الخلفية (يجهّز الطلب حسب القواعد ولا يراه الزبون). المخزن = قاعدة البيانات (فيه المكونات المحفوظة ويأخذ منه الطباخ ما يحتاجه).
  5. علّل: لا تتعامل الواجهة الأمامية مباشرة مع قاعدة البيانات.
    لأن الواجهة الخلفية هي الوسيط بينهما؛ فهي تستقبل الطلب وتعالجه وتطبّق قواعد التطبيق، ثم تطلب البيانات من قاعدة البيانات وتعيد النتيجة للواجهة الأمامية.
  6. وزّع مهام موقع مشاركة الفيديو على الطبقات الثلاث.
    الأمامية: عرض شاشات تشغيل الفيديو والبحث واستقبال إجراءات المستخدم. الخلفية: اختيار الفيديوهات الموصى بها وتجميع عدد المشاهدات. قاعدة البيانات: تخزين بيانات الفيديو ومعلومات المستخدمين وسجل المشاهدة.
  7. ما فائدة تنظيم المسؤوليات في طبقات واضحة؟
    يسهّل تحديد مكان الخطأ وإصلاحه، ويسهّل تطوير كل جزء دون التأثير على باقي الأجزاء.
  8. اذكر ثلاث ملاحظات مهمة على نموذج الطبقات الثلاث.
    1) قاعدة البيانات قد تشمل قواعد بيانات أو ملفات وكائنات مخزّنة أو ذاكرة مخبأة أو خدمات بيانات خارجية. 2) النموذج تعليمي وليس إلزاميًا، وقد لا توجد قاعدة بيانات تقليدية أصلًا. 3) بعض الأنشطة قد تتداخل بين الطبقات.

السؤال الرابع: الأسئلة المقالية

  1. قارن بين العميل والخادم مع ذكر مثال لكل منهما.
    العميل: برنامج أو جهاز يرسل طلبًا إلى خدمة أخرى، أي الجانب الذي يطلب البيانات أو المعالجة (متصفح الويب، تطبيق الهاتف). الخادم: الجانب الذي يستقبل الطلبات من العملاء ويعالجها ويعيد الاستجابات (خادم الويب، خادم التطبيقات).
  2. فرّق بين HTTP وHTTPS.
    HTTP: بروتوكول نقل النص التشعبي لتبادل الرسائل بين عميل وخادم الويب، وهو غير مشفّر. HTTPS: استخدام HTTP عبر اتصال TLS آمن، يحمي سرية الاتصال وسلامته ويساعد على مصادقة الخادم.
  3. لماذا يجب استخدام HTTPS في صفحات تسجيل الدخول؟
    لأن كلمة المرور بيانات سرية، وHTTPS يشفّرها أثناء النقل فلا يستطيع أحد سرقتها أو تعديلها.
  4. فرّق بين طريقتي GET وPOST مع مثالين لكل منهما.
    GET: لطلب مورد أو بيانات من الخادم (عرض صفحة ويب، استرجاع نتائج البحث، طلب الجدول الدراسي). POST: لإرسال بيانات ليعالجها الخادم (معلومات تسجيل الدخول، نشر تعليق، رفع درجات الطلاب).
  5. اذكر معنى رموز الحالة 200 و404 و500، وأين المشكلة في كل منها.
    200: نجاح ولا توجد مشكلة. 404: المورد غير موجود بهذا العنوان؛ العنوان غير صحيح أو الصفحة حُذفت. 500: خطأ داخلي في الخادم؛ المشكلة في جانب الخادم.
  6. عرّف API وJSON، ووضّح العلاقة بينهما.
    API: مجموعة قواعد واضحة تسمح لبرنامج بطلب بيانات أو وظائف من برنامج آخر. JSON: صيغة نصية شائعة لتمثيل البيانات المهيكلة (مفتاح : قيمة). العلاقة: قد تعيد API البيانات بصيغة JSON.
  7. اشرح خطوات طلب صفحة ويب منذ كتابة عنوانها حتى عرضها.
    1) المتصفح (العميل) يرسل طلب HTTP بطريقة GET إلى الخادم. 2) الخادم يستقبل الطلب ويعالجه. 3) الخادم يرسل الاستجابة ومعها رمز الحالة (مثل 200). 4) المتصفح يعرض الصفحة للمستخدم.
  8. اقرأ بيانات JSON التالية واستخرج المفاتيح والقيم، وحدد نوع كل قيمة: {"student": "Ali", "grade": 95, "city": "Giza"}
    المفاتيح: student وgrade وcity. القيم: "Ali" (نص)، 95 (رقم بدون تنصيص)، "Giza" (نص).
